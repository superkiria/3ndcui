# Прототип управления шардами

Интерактивный интерфейс на React, TypeScript и Vite для демонстрации операций с мастерами и репликами. Все данные находятся в памяти браузера; сервер приложения, база данных и внешние API не используются. Перезагрузка страницы восстанавливает исходное состояние. Все операции — симуляция.

## Локальный запуск

Можно запустить `./run.sh`: он использует установленный Node.js (или временную копию в этой среде) и установит зависимости, если они отсутствуют.

Нужен Node.js 22.12+ (или 24 LTS) и npm.

```sh
npm install
npm run dev
```

Откройте адрес, который напечатает Vite (обычно http://127.0.0.1:5173).

```sh
npm run build     # проверка TypeScript и production-сборка
npm run preview   # просмотр собранного приложения
```

## Структура проекта

- `src/model.ts` — демо-данные, сценарии и правила допустимости переключений и перемещений.
- `src/main.tsx` — интерфейс, состояние React, симуляция операций и история текущей сессии.
- `src/styles.css` — оформление и адаптация интерфейса.
- `AGENTS.md` — краткий ориентир для агентов, работающих с кодом.

## Демонстрация

- Мелкие шрифты (исходно 12–14 px) увеличены на 4 pt. Номера экземпляров отображаются минимум двумя цифрами (№01, №02, …, №10), в том числе в выборе мастера, уведомлениях и истории; поиск принимает номера с ведущим нулём и без него. Обычный текст и длинные фразы используют пропорциональный шрифт. Моноширинный сохранён для коротких заголовков, терминов, отставания, таблиц, лейблов и полей выбора. Фразы из четырёх слов и более, включая длинные заголовки и пояснения в истории, используют пропорциональный шрифт.
- Ниже управления демо расположен блок «Текущий режим»: исходно 🎯 Моно, альтернативный режим — 🌐 Мульти. Кнопка переключения запускает симуляцию публикации флага режима в ZooKeeper, ожидания переключения всех подов shard-egress и завершения перехода. Сервис shard-egress показан отдельно от топологии ЦОД: 372 пода в трёх пространствах имён. Постоянно видны два общих счётчика — поды в режиме «Моно» и поды в режиме «Мульти»; их сумма всегда равна 372. Во время ожидания поды переключаются по одному каждые 15 мс: счётчики и полоса прогресса непрерывно обновляются, переключение всех 372 подов занимает около 5,6 секунды. Публикация флага и завершение занимают случайное время от 0 до 5 секунд каждый. Индивидуальные статусы подов не отображаются. Текущий режим меняется только после завершения перехода, результат и этапы сохраняются в блоке, операция отражается в истории. Реальные ZooKeeper и поды не используются. Режим не меняет топологию и правила операций с мастерами.
- Цвета ЦОД основаны на [палитре Ubuntu](https://design.ubuntu.com/brand/colour-palette): A — тёмный оранжевый с коричневым оттенком (#A33B16, затемнённый Ubuntu orange), B — баклажановый, C — тёплый серый. Фоны светлые, акценты цветные; обозначение реплики нейтральное с контуром, предупреждения жёлтые. Цвета повторяются в заголовках таблицы, полях выбора исходного и целевого ЦОД и вариантах нового мастера при одиночном переключении; буквенные обозначения ЦОД сохраняются.
- 12 групп G01–G12, 36 экземпляров, изначально по 4 мастера в каждом ЦОД. У реплик любой группы можно включать и отключать репликацию. Отключённая реплика не подходит для переключения мастера.
- Статус мастера — `MASTER_RW`, реплики с включённой репликацией — `REPLICA_A`, с отключённой — `REPLICA_OFFLINE` на сером фоне. При одиночном и массовом переключении, начиная с этапа отключения старого мастера и до завершения операции группы, прежний мастер показан как `MASTER_R`, новый — как `MASTER_W`. Статусы обновляются одновременно в таблице и панели группы. После завершения новый мастер получает `MASTER_RW`, прежний — `REPLICA_A`. На предварительной проверке и при её ошибке статусы остаются исходными.
- Поиск: `G01`, `G0` или точный номер `2`, `№2`, `#2`. Поиск сочетается с фильтром «Только проблемные». Сводка всегда охватывает всю систему.
- Кнопка «Открыть G01» сразу открывает группу для демонстрации. Строки таблицы также открывают панель; с клавиатуры используйте кнопку с ID группы.
- Для переключения выберите доступную реплику с включённой репликацией и отставанием не более 1000 мс и подтвердите маршрут. Каждый этап симуляции длится случайное время от 0 до 5 секунд: проверка, отключение старого мастера, применение изменений репликации, включение нового мастера и завершение. Широкая панель группы показывает три экземпляра слева и ход переключения или изменения репликации справа; на узком экране блоки идут друг под другом. Закрытие панели не прерывает операцию.
- Кнопка «Экстренно вывести мастер» рядом с обычным переключением доступна только в панели одной группы. Выберите доступную реплику с включённой репликацией и подтвердите экстренный маршрут. Отставание не ограничивает выбор, доступность прежнего мастера не требуется. Ожидание Kafka-репликации пропускается; этапы: проверка целевой реплики, принудительное отключение прежнего мастера, включение нового и завершение, каждый от 0 до 5 секунд. Во время передачи прежний мастер показан как `MASTER_OFFLINE`, новый — `MASTER_W`. После завершения новый мастер получает `MASTER_RW`, прежний остаётся `MASTER_OFFLINE` на сером фоне, недоступен и с отключённой репликацией; он не становится репликой и не может быть целью последующих переключений или массового перемещения. Восстановление такого экземпляра запускается кнопкой «Восстановить» в панели группы. Панель и история отмечают экстренную операцию. Флажок ошибки применяется к её предварительной проверке, оставляя состояние исходным. Массовое перемещение использует только плановые правила. Все действия остаются симуляцией.
- Кнопка «Восстановить» у экземпляра `MASTER_OFFLINE` сразу переводит его в `RECOVERY`. Симуляция восстановления содержит три шага с названиями `1`, `2`, `3`, каждый длится случайное время от 0 до 5 секунд. После завершения всех шагов экземпляр становится доступной репликой `REPLICA_A` с включённой репликацией и нулевым отставанием; текущий мастер не меняется. У восстановленной реплики доступны обычные кнопки управления репликацией: отключение даёт `REPLICA_OFFLINE`, повторное включение возвращает `REPLICA_A`. Она может участвовать в одиночном переключении и массовом перемещении по обычным правилам. Во время восстановления остальные операции, сценарии и сброс заблокированы. Закрытие панели не прерывает восстановление; этапы и результат сохраняются в панели и истории. Загрузка сценария или сброс очищает результат восстановления.
- Кнопка «Распределение мастеров» открывает отдельную панель с матрицей из 36 ячеек: 12 строк групп и три колонки ЦОД, как в основной таблице. Старая панель выбора исходного ЦОД удалена. Нажатие ячейки назначает мастера по плану для одной группы; текущий мастер отмечен точкой, выбранный — галочкой. Изначально план повторяет текущее распределение. Можно задать переносы из разных ЦОД в одном плане, а неизменённые группы остаются на месте. Счётчики показывают текущее и запланированное число мастеров в каждом ЦОД. Ячейки используют те же статусы, что основная таблица: MASTER_RW, REPLICA_A, REPLICA_OFFLINE, MASTER_OFFLINE, RECOVERY и промежуточные MASTER_R и MASTER_W. Причина недопустимости цели показана отдельно под статусом; её выбор блокирует весь план до исправления. До нажатия «Начать перемещение» роли не меняются. Перед запуском проверяются все изменённые группы. Затем они переключаются строго по очереди G01–G12, с пятью этапами по 0–5 секунд на каждый перенос. В матрице, основной таблице и панели группы отображаются промежуточные статусы MASTER_R и MASTER_W; роль меняется после завершения этапов группы. Прогресс и история сохраняют исходный и целевой ЦОД каждой группы. Во время выполнения редактирование плана и остальные операции заблокированы; панель можно закрыть и снова открыть через «Показать прогресс». После завершения можно изменить назначения для нового запуска или нажать «Сбросить план», чтобы вернуться к текущему распределению. Загрузка сценария и сброс очищают план и закрывают панель. Все переносы — симуляция.
- Сценарии отставания и недоступности изменяют реплику №02 в G01; реплика №03 остаётся доступной для переключения. Каждый сценарий заново загружает данные и очищает историю.
- Флажок ошибки применяется только к следующему одиночному переключению мастера. Ошибка происходит на проверке, до изменения ролей; повторная попытка доступна. Отмена выбора не расходует флажок.
- Включение и отключение репликации — симуляция с этапами предварительной проверки, публикации карты распределения и проверки после изменения. Каждый этап длится случайное время от 0 до 5 секунд. Состояние реплики меняется на этапе публикации карты. Панель сохраняет все этапы и результат после завершения операции, как при переключении мастера; при запуске следующей операции справа показывается только её ход. Пока идёт любая операция, переключения, управление репликами, массовое перемещение, сценарии, флажок ошибки и сброс заблокированы. История создаётся при старте и обновляется по ходу операции.
- Пока переключается режим, остальные операции, сценарии и сброс заблокированы; переключение режима также недоступно во время других операций. Загрузка сценария восстанавливает режим «Моно» и очищает прогресс его переключения.
- «Сбросить демо» восстанавливает данные и режим «Моно», очищает историю, прогресс режима, поиск и фильтр, выключает ошибку и закрывает панель.

Недоступный мастер сохраняет роль и блокирует плановое переключение; экстренное переключение допускается. Отдельного сценария недоступности мастера нет.

## Проверка массового перемещения

Откройте «Распределение мастеров»: матрица содержит все 36 экземпляров независимо от поиска и фильтра основной таблицы. Выберите для G01 ЦОД C, для G02 ЦОД A и для G03 ЦОД B. До запуска роли и текущие счётчики не меняются; план показывает три переноса. Запустите перемещение и проверьте последовательное выполнение, промежуточные статусы и маршруты в истории. Закройте панель во время операции и снова откройте прогресс. После завершения остальные девять групп остаются на месте, у каждой группы ровно один мастер. Повторный запуск без новых изменений недоступен.

В сценариях отставания и недоступности выберите G01 → ЦОД B и ещё одну допустимую цель для другой группы: запуск всего плана заблокирован, роли не меняются. Выбор G01 → ЦОД C позволяет продолжить. Отключённая реплика также блокирует план. Проверьте сброс плана, очистку при загрузке сценария и сбросе демо, управление кнопками с клавиатуры и отсутствие горизонтальной прокрутки на узком экране.
