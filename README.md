# Прототип управления шардами

Интерактивный интерфейс на React, TypeScript и Vite для демонстрации операций с мастерами и репликами. Все данные находятся в памяти браузера; сервер приложения, база данных и внешние API не используются. Перезагрузка страницы восстанавливает исходное состояние. Все операции — симуляция.

## Локальный запуск

Можно запустить `./run.sh`: он использует установленный Node.js (или временную копию в этой среде) и установит зависимости, если они отсутствуют.

Нужен Node.js 22.12+ (или 24 LTS) и npm.

```sh
npm install
npm run dev
```

Откройте адрес, который напечатает Vite (обычно http://127.0.0.1:5173).

```sh
npm run build     # проверка TypeScript и production-сборка
npm run preview   # просмотр собранного приложения
```

## Структура проекта

- `src/model.ts` — демо-данные, сценарии и правила допустимости переключений и перемещений.
- `src/main.tsx` — интерфейс, состояние React, симуляция операций и история текущей сессии.
- `src/styles.css` — оформление и адаптация интерфейса.
- `AGENTS.md` — краткий ориентир для агентов, работающих с кодом.

## Демонстрация

- 12 групп G01–G12, 36 экземпляров, изначально по 4 мастера в каждом ЦОД. Нечётные группы асинхронные; у их реплик можно включать и отключать репликацию. Отключённая реплика не подходит для переключения мастера.
- Поиск: `G01`, `G0` или точный номер `2`, `№2`, `#2`. Поиск сочетается с фильтром «Только проблемные». Сводка всегда охватывает всю систему.
- Кнопка «Открыть G01» сразу открывает группу для демонстрации. Строки таблицы также открывают панель; с клавиатуры используйте кнопку с ID группы.
- Для переключения выберите доступную реплику с включённой репликацией и отставанием не более 1000 мс и подтвердите маршрут. Каждый этап симуляции длится случайное время от 3 до 7 секунд: проверка, отключение старого мастера, применение изменений репликации, включение нового мастера и завершение. Широкая панель группы показывает три экземпляра слева и ход переключения или изменения репликации справа; на узком экране блоки идут друг под другом. Закрытие панели не прерывает операцию.
- Массовое перемещение переводит всех мастеров из выбранного исходного ЦОД в выбранный целевой ЦОД. Сначала проверяются все затронутые группы; если хотя бы одна целевая реплика не подходит, состояние групп не меняется. Затем группы перемещаются по очереди, и для активной группы показаны те же пять этапов и состояния, что при одиночном переключении; каждый этап длится от 3 до 7 секунд. Роль мастера меняется после завершения этапов группы. Мастера других ЦОД остаются на месте.
- Сценарии отставания и недоступности изменяют реплику №2 в G01; реплика №3 остаётся доступной для переключения. Каждый сценарий заново загружает данные и очищает историю.
- Флажок ошибки применяется только к следующему одиночному переключению мастера. Ошибка происходит на проверке, до изменения ролей; повторная попытка доступна. Отмена выбора не расходует флажок.
- Включение и отключение репликации — симуляция с этапами предварительной проверки, публикации карты распределения и проверки после изменения. Каждый этап длится случайное время от 3 до 7 секунд. Состояние реплики меняется на этапе публикации карты. Панель сохраняет все этапы и результат после завершения операции, как при переключении мастера; при запуске следующей операции справа показывается только её ход. Пока идёт любая операция, переключения, управление репликами, массовое перемещение, сценарии, флажок ошибки и сброс заблокированы. История создаётся при старте и обновляется по ходу операции.
- «Сбросить демо» восстанавливает данные, очищает историю, поиск и фильтр, выключает ошибку и закрывает панель.

Недоступный мастер сохраняет роль и блокирует плановое переключение. Отдельного сценария недоступности мастера нет.
