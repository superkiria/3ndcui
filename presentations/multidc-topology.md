Репликация действует внутри группы; схема не задаёт транспорт репликации или связь с контурами Main / StandIn.

## 6. Плановое переключение мастера

**На слайде:**

- До
- A: MASTER_RW     B: REPLICA_A
- После
- A: REPLICA_A     B: MASTER_RW
- Проверки → отключение старого → репликация → включение нового

**Заметки ведущему — только для устного объяснения:**

Показать G01 → ЦОД B. В демо нужны доступный текущий мастер, доступная реплика, включённая репликация и отставание не более 1000 мс. 1000 мс — правило прототипа, а не утверждённый производственный порог. Этапы: проверка, отключение старого мастера, применение изменений репликации, включение нового мастера, завершение. Ошибка предварительной проверки не меняет роли.

Устные пояснения и вопросы (не показывать на слайде):
Внутри одной группы: выбранная реплика становится мастером.

Какие проверки обязательны? Кто имеет право подтвердить переключение?

В демо: оба доступны, репликация включена, отставание ≤ 1000 мс.
Ошибка предварительной проверки оставляет роли без изменений.

## 7. Экстренное переключение и восстановление

**На слайде:**

- Экстренное переключение
- Доступная реплика; репликация включена. / Без ожидания Kafka-репликации.
- Восстановление
- MASTER_OFFLINE → RECOVERY / → REPLICA_A

**Заметки ведущему — только для устного объяснения:**

Демо не требует доступности прежнего мастера и не ограничивает отставание целевой реплики. Реплика обязана быть доступна и иметь включённую репликацию. Ожидание Kafka-репликации пропускается. Неполные данные — риск, а не утверждение, что потери обязательно произойдут. Реальное гарантированное отключение прежнего мастера и исключение одновременной записи двумя мастерами следует обсудить. Восстановление имеет условные шаги 1, 2, 3, а не реальный регламент.

## 8. Распределение мастеров по ЦОД

**На слайде:**

- Пример плана
- G01: A → C / G02: B → A / G03: C → B
- Правила демо
- Сначала проверка всего плана. / Затем переносы по очереди. / Остальные группы остаются на месте.

**Заметки ведущему — только для устного объяснения:**

В демо матрица имеет 12 групп и три ЦОД. План не меняет роли до запуска. Предварительно проверяются все изменённые группы; блокировка любой цели не позволяет запустить весь план. После проверки группы переключаются последовательно G01–G12. Это не означает атомарности всего плана после старта. Поведение при сбое в середине нужно определить.
